# План работ: лабораторная 2

Репозиторий `artwork-exhibition-backend`, ветка `sprint-2-artwork-database` от `sprint-1-artwork-catalog`. Начинать после защиты лабораторной 1. Замечания прошлой защиты закрыть в том же `.doc`: текст и скриншот на каждое.

## 1. Хранилище

- [ ] Сервисы PostgreSQL и Adminer в Compose рядом с MinIO.
- [ ] Таблицы из `документация/модель-данных.md`, миграция, без `ON DELETE CASCADE`.
- [ ] ER в StarUML: столбцы, типы, длины, PK, FK.
- [ ] Наполнение Adminer: черновик, экспозиция, снятая работа, посетители, отметки.

## 2. Доступ к данным

- [ ] Модели GORM.
- [ ] Пять операций ORM: лента (одна строка), черновик, плитка с годом, создание, публикация.
- [ ] Снятие с показа: `UPDATE` через `database/sql`.
- [ ] Шаблоны лаб. 1 читают БД; главная и автор тоже.

## 3. Сценарии формы

- [ ] Нет черновика: «Далее» создаёт строку и пишет неверные ключи медиа.
- [ ] Черновик есть: форма заполнена, кнопка «Опубликовать».
- [ ] Публикация требует название, этикетку, год и зал.
- [ ] Битый ключ показывает `static` изображение и видео по умолчанию.
- [ ] URL снятого произведения не открывает карточку.

## 4. Защита

- [ ] Скриншоты 1–22 по порядку показа.
- [ ] Ответы: виды БД, SQL, курсоры, ORM, миграции, чистая архитектура.

Критерий готовности: правка года, зала и числа строк `visitor_appreciations` в Adminer видна на плитках и в ленте без ручных массивов в обработчике.
