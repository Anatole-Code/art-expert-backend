# Лабораторная 2

Источник: [Лабораторная 2](https://github.com/iu5git/Web#лабораторная-2). Репозиторий `artwork-exhibition-backend`, ветка `sprint-2-artwork-database`.

## Цель

Структура PostgreSQL по теме и те же шаблоны уже читают БД. Наполнение через Adminer. ER в одном файле StarUML.

## Поведение

- Получение, поиск, создание и публикация — GORM.
- Снятие с показа на плитке — `UPDATE ... SET display_status = 'withdrawn'` через SQL, без ORM.
- Лента: БД отдаёт одну строку.
- «Далее» на черновике создаёт строку, только если черновика у куратора ещё нет. Ключи фото и видео — неверные URL, файлы не загружаются.
- «Опубликовать» после этикетки, года и зала ставит `on_display`.
- Если черновик уже есть, форма открывается заполненной.
- Пустые или недоступные медиа — файлы по умолчанию из каталога сервера.
- Снятое по прямой ссылке не показывается.
- Отметки не ставятся, только число из `visitor_appreciations`.

## Порядок показа

1. Adminer: снять произведение статусом, `select`.
2. Три страницы: фильтр, снятие, переход на URL снятого, добавление, публикация, `select` после каждого изменения.
3. Правка года, зала и числа отметок в БД видна в приложении.
4. В коде модели, пять обращений ORM и один SQL `UPDATE`.
5. Фото и видео по умолчанию в HTML.

Контрольные вопросы: виды БД, SQL, курсоры, ORM, модель и миграции, чистая архитектура.
